# 게임 규칙 분석 (코드 기반)

`01_Scripts/` 전체와 `05_Data/01_MapData/*.json`을 읽고 정리한 문서다.
추측이 아니라 실제 코드 경로를 근거로 적었고, 규칙 검증용 시뮬레이터로 기존 8개 맵의
클리어 경로를 전수 탐색해 확인했다.

## 1. 한 줄 요약

> **격자 턴제 퍼즐. 체력이 곧 감정이고, 감정이 곧 이동력과 공격력이다.
> 이동력을 쓰고 남은 만큼만 때릴 수 있다.**

플레이어는 방향 하나를 입력한다. 그 한 번의 입력이 "이동"이자 "공격"이다.
둘은 같은 자원(움직임)을 나눠 쓴다.

## 2. 턴 파이프라인

`ActionManager.run_turn()` (01_Scripts/Systems/AutoLoad/ActionManager.gd:89)

```
입력 → UndoManager.pre_action()  (모든 Element의 상태 스냅샷)
     → player.action_dir(dir, 0) (게임 로직 실행. 이 안에서 record_new()로 사건 기록)
     → AnimationQueue.play_all() (기록된 사건을 tick 순서로 재생)
     → UndoManager.commit_turn() (히스토리 적재, 최대 30턴)
     → StageDirector.flush_pending_map_change() (맵 전환은 턴이 끝난 뒤에)
```

핵심 설계: **게임 로직은 애니메이션을 모른다.** 로직은 `ActionManager.record_new()`로
"무슨 일이 일어났는가"만 보고하고, 연출은 `tick` 값에 따라 나중에 일괄 재생된다.
그래서 로직상으로는 한 턴이 즉시 끝나지만, 화면에서는 순차적으로 보인다.

### 입력 (InputManager.gd)

| 조작 | 키보드 | 터치 |
|---|---|---|
| 이동/공격 | WASD, 방향키 | 스와이프 (50px 이상, 0.5초 이내) |
| 상호작용 | Space, Enter | 싱글 탭 (현재 구독자 없음 = 사실상 무동작) |
| 되돌리기 | Z | 더블 탭 (0.25초 이내) |

턴 처리 중 들어온 입력은 `InputBuffer`가 0.2초간 1슬롯만 보관했다가 흘려보낸다.
연타하면 마지막 의도만 살아남는다.

## 3. 감정 시스템 — 이 게임의 심장

`Player.gd:28-41`. 체력이 바뀌는 순간(`_set_hp`) 자동으로 감정이 갱신되고,
감정이 공격력과 이동력을 **덮어쓴다.** 플레이어가 따로 고를 수 없다.

| 감정 | 체력(최대 6) | 이동력 | 공격력 | 성격 |
|---|---|---|---|---|
| 평온 CALM | 4 ~ 6 | 1 | 1 | 느리고 약하지만 **정밀하다** |
| 화남 ANGRY | 2 ~ 3 | 1 | 2 | 정밀하면서 강하다 (최적 구간) |
| 격노 RAGE | 1 | 2 | 2 | 강하고 빠르지만 **멈출 수 없다** |

여기서 나오는 게 이 게임의 정체성이다.

- **체력은 목숨이 아니라 다이얼이다.** 다치는 게 곧 강해지는 것이다.
- **회복은 너프다.** 힐 아이템은 "약해지는" 아이템이다. 단, 정밀함을 되찾는 아이템이기도 하다.
- **격노는 축복이자 저주다.** 이동력 2는 구멍을 건너뛰게 해주지만,
  동시에 "1칸만 가기"를 불가능하게 만든다.

## 4. 이동과 공격 — 하나의 자원

`Unit.action2()` (Unit.gd:66), `Unit.move_to()` (Unit.gd:88)

```gdscript
var res := move_to(dir, spd, tick)          # 한 칸씩 실제로 이동
var remain_atk: int = atk_pow - res["moved"]  # ← 이동한 만큼 공격력이 깎인다
if res["blocked"] and remain_atk > 0:
    attack(remain_atk, res["dir"], tick, res["pos"])
```

규칙:

1. 입력한 방향으로 **이동력만큼** 한 칸씩 전진한다.
2. 막히면(`can_pass` 실패) 거기서 멈춘다.
3. **막혔을 때만** 공격이 발생한다. 피해량 = `공격력 - 이동한 칸수`.
4. 이동력을 다 쓰고 멈춘 경우(막히지 않음)엔 공격이 없다.

현재 수치로 정리한 실제 타격표:

| 상태 | 붙어서 때림 (0칸 이동) | 1칸 가다 막힘 | 2칸 이동 |
|---|---|---|---|
| 평온 (이동1/공격1) | **1** | 불가 (이동력 소진) | 불가 |
| 화남 (이동1/공격2) | **2** | 불가 | 불가 |
| 격노 (이동2/공격2) | **2** | **1** | 0 (공격 없음) |

→ **이동력 1인 상태에서는 "붙어서 때리기"만 가능하다.** 이동과 공격이 같은 턴에
동시에 성립하는 건 격노 상태뿐이고, 그때는 위력이 절반으로 깎인다.

### 벽 파괴 조건

`Wall.gd:37`. 벽의 `ma`(min_atk)가 0이면 파괴 불가, 그 외엔 `ma <= 피해량`이면 파괴.
현재 공격력 최댓값이 2이므로:

- `ma: 1` 벽 → 누구나 붙어서 때리면 부순다.
- `ma: 2` 벽 → **체력 3 이하(화남/격노)에서 붙어서 때려야만** 부순다.
- `ma: 3` 이상 → 플레이어 단독으로는 영원히 못 부순다. (상자를 써야 함)

파괴에 실패하면 `on_parryed` 연출이 나간다. "때렸는데 튕겼다"는 피드백이 따로 있다.

## 5. 오브젝트별 규칙

| 오브젝트 | 막힘 | 피격 | 발동 시점 | 규칙 |
|---|---|---|---|---|
| `wall` | O | O | 피격 시 | `ma`≥1이고 피해≥`ma`면 파괴. `ma`:0은 불괴 |
| `trap` | X | O | **진입(entered)** | `atk`만큼 피해. `once`면 1회 후 소멸 |
| `healItem` | X | X | **진입(entered)** | `heal`(기본 1)만큼 회복 후 소멸. 공격 불가 |
| `moveBox` | O | O | 피격 시 | 맞은 힘 P만큼 반대 방향으로 P칸 이동 + 남은 힘으로 타격 |
| `clear` / `worldPortal` | X | X | **정착(settled)** | 맵 전환. 지나가는 건 안 되고 **멈춰야** 발동 |

### 진입(entered) vs 정착(settled) — 아주 중요한 구분

`GridManager`는 두 개의 다른 시그널을 쏜다.

- `element_entered` : 한 칸 들어설 때마다. **지나가기만 해도 발동.**
  → 함정과 힐 아이템이 여기 붙어 있다.
- `element_settled` : 이동이 완전히 끝났을 때 1회. **최종 착지 지점에서만.**
  → 포탈이 여기 붙어 있다.

그래서:
- 격노로 질주하면 **지나치는 칸의 함정도 전부 밟는다.**
- 격노로 목표 포탈 위를 지나가면 **클리어되지 않는다.** 정확히 멈춰야 한다.

### 상자(moveBox) — 힘의 전달자

`MoveBox.gd:25`

```gdscript
func on_hit(atk_data: AtkData) -> bool:
    move_speed = atk_data.dmg      # 맞은 힘 = 이동력
    atk_pow = atk_data.dmg          # 맞은 힘 = 공격력
    var dir = cur_position.subtract(atk_data.from).normalized()
    action_dir(dir, atk_data.tick)  # 플레이어와 똑같은 이동/공격 루틴을 탄다
```

상자는 플레이어와 **완전히 동일한 규칙**으로 굴러간다. 따라서:

- **밀기 거리 = 내 감정.** 평온이면 1칸, 화남/격노면 2칸 날아간다.
- **거리만큼 힘이 감쇠한다.** 벽에 붙어 있는 상자를 2로 밀면 0칸 이동 후 남은 2로 벽을 때린다.
  벽에서 1칸 떨어진 상자를 2로 밀면 1칸 이동 후 남은 1로만 때린다.
  → **`ma:2` 벽을 상자로 부수려면 상자가 벽에 밀착해 있어야 한다.**
- 상자가 함정 칸에 들어가면 함정이 발동하지만, 상자는 자기 자리에서 맞은 것이라
  방향이 0이 되어 움직이지 않는다. → **일회성 함정을 상자로 대신 밟아 없앨 수 있다.**
- 상자가 힐 아이템 칸을 지나면 힐이 소모된다. → **상자로 힐을 치울 수 있다.**
- 상자가 구멍 위에서 멈추면 낙하해 사라진다. (구멍을 메우지는 못한다)

### 낙하

`Unit.action2()` 마지막. **이동이 전부 끝난 뒤 최종 위치**에만 타일 유무를 검사한다.

```gdscript
if not GridManager.has_tile(cur_position.x, cur_position.y):
    is_fallen = true
```

`can_pass()`는 구멍을 막지 않는다. 즉 **구멍은 지나갈 수 있고, 그 위에서 멈추면 떨어진다.**
→ 이동력 2(격노)면 1칸짜리 구멍을 뛰어넘는다. 이게 격노의 존재 이유다.

## 6. 코드에서 창발한 규칙들 (기획서에는 없지만 실제로 존재하는 것)

기존 맵들이 이미 이걸 활용하고 있다. 앞으로의 레벨 디자인의 주 재료다.

### (a) 홀짝 고정 (parity lock)

격노 상태에선 항상 2칸씩 움직이므로 **좌표의 홀짝이 보존된다.**
홀짝을 바꾸려면 "1칸 가고 막히는" 상황이 필요하다 —
즉 **벽, 상자, 맵 가장자리**가 유일한 홀짝 전환 장치다.

### (b) 브레이크(제동) 문제

격노 상태에서 특정 칸에 정확히 서려면 그 **다음 칸에 막을 것**이 있어야 한다.
- 벽 / 맵 가장자리 → 고정 브레이크
- 상자 → 플레이어가 직접 설치하는 이동식 브레이크
- 힐 아이템 → 밟는 순간 이동력이 1로 떨어지는 **감속기**

### (c) 진행 중 감정 변화

`move_to()`의 `remain`은 지역 변수라 이동 중에 체력이 변해도 **그 턴의 남은 이동 칸수는
바뀌지 않는다.** 반면 `atk_pow`는 이동이 끝난 뒤에 다시 읽는다.
→ 질주 중에 힐을 먹어도 그 턴은 끝까지 2칸 간다. 감속은 다음 턴부터.

### (d) 죽어도 관성은 유지된다

`Unit.died()`는 플래그만 세운다. 이동 루프는 계속 돈다.
치명타를 밟아도 그 턴의 이동은 끝까지 수행된다. (코드 주석: "A2: 죽어도 관성 유지")

## 7. Undo — 이 게임의 안전망

`UndoManager` + `ActionManager.run_undo()`

- 매 턴 시작 시 **모든 Element의 논리 상태를 통째로 스냅샷**한다. (최대 30턴)
- 되돌릴 때는 상태를 복원한 뒤, 기록된 `undo_action`들을 tick 역순으로 재생한다.
- 되돌리기 후 `sync_visuals()`가 안전망으로 논리 상태와 화면을 강제 일치시킨다.

**설계적 의미:** 실패에 비용이 없다. 죽어도, 구멍에 빠져도 더블 탭 한 번이면 돌아온다.
그래서 이 게임의 레벨은 "죽지 않게 조심하는 것"이 아니라
**"일부러 죽어보면서 규칙을 알아내는 것"**을 전제로 설계해도 된다.
실제로 기존 맵들이 그렇게 만들어져 있다.

## 8. 스테이지 진행 구조

```
00_00 (메인 허브) ──worldPortal──> 01_00 (1월드 허브) ──worldPortal──> 01_01 ~ 01_10
                                        ^                                  │
                                        └──────────clear 포탈───────────────┘
```

- 맵 파일명은 `MapLoader`가 `%02d_%02d.json`으로 조립한다. (world_stage)
- `clear` 포탈을 밟으면 `StageManager.clear_stage()`로 진행도를 저장하고
  해당 월드 허브로 복귀한다. 이때 방금 깬 스테이지의 월드 포탈 위에 플레이어가 배치된다.
- 진행도는 `user://save.cfg`에 ConfigFile로 저장된다.
- `is_unlocked()`는 "직전 스테이지를 깼는가"로 판정하지만,
  **현재 허브 맵의 월드 포탈에는 잠금 검사가 걸려 있지 않다.** (전부 바로 진입 가능)

## 9. 검증 결과 — 기존 8개 맵 전수 탐색

규칙을 그대로 이식한 시뮬레이터로 BFS 전수 탐색한 결과다.
(모든 맵이 클리어 가능했고, 각 스테이지의 의도가 수치로 확인됐다)

| 맵 | 최단 수 | 강제되는 감정 | 가르치는 것 |
|---|---|---|---|
| 01_01 첫 번째 스테이지 | 10 | 없음 (평온) | 이동은 1칸씩. 구멍은 죽음. 돌아가야 한다 |
| 01_02 두 번째 스테이지 | 5 | 없음 (평온) | 벽에 부딪히면 그게 공격이다 (`ma:1`) |
| 01_03 임시맵 | 16 | **화남 필수** | **함정은 자원이다.** 일부러 두 번 밟아 `ma:2`를 부순다 |
| 01_04 | 22 | 격노 필수 | 함정 연쇄로 단번에 격노 진입, 구멍 건너뛰기 |
| 01_05 | 14 | 격노 필수 | 구멍 건너뛰기 + 힐로 홀짝 조정 |
| 01_06 | 13 | 격노 필수 | 함정 왕복으로 체력 미세 조정 |
| 01_07 | 23 | **격노 필수** | **체력 산수.** 힐(+1)과 함정(-2)로 정확히 1을 만든다 |

01_03의 실제 최적 해답(시뮬레이터 출력):

```
U U L L L D D U D U U R R R R R
  → (0,2) 함정 진입 hp 6→4
  → (0,2) 다시 진입    hp 4→2  [화남 진입]
  → 되돌아와 ma:2 벽을 붙어서 타격 → 파괴 → 클리어
```

01_07은 `6 -2→ 4 +1→ 5 -2→ 3 -2→ 1` 로 **정확히 1을 만들어야만** 시작되는 맵이다.
체크무늬 구멍밭이라 이동력 2가 아니면 한 칸도 못 가고, 체력이 2가 되면 그 자리에 갇힌다.
지도 곳곳의 힐 아이템은 도움이 아니라 **함정**이다 (밟으면 격노가 풀려 고립된다).

## 10. 작업 중 발견한 이슈

| 위치 | 내용 | 심각도 |
|---|---|---|
| `Portal.gd:22` | 포탈이 **엘리먼트 종류를 가리지 않고** 발동한다. 상자가 클리어 포탈 위에 멈추면 스테이지가 클리어된다 (주석에도 "일단은 elm 상관없이 발동"이라 적혀 있음) | 레벨 설계 제약. 목표 근처에 상자를 두면 의도치 않게 풀림 |

| `01_00.json` | `(3,0)`에 벽이 **두 개** 겹쳐 있다 (불괴 1개 + `ma:1` 1개). 파괴해도 통과 불가 | 데이터 오류 |
| `ㄷㅈ.json`, `ㅅㄷㄴㅅ.json` | 파일명이 오타(한글 자모). `MapLoader`가 world/stage로 파일명을 조립하므로 **절대 로드되지 않는** 사문서 | 정리 대상 |
| `StageDirector.gd:67` | `unload_stage()`에서 `worldPortals`를 초기화하지 않음 (주석에 TODO로 남아 있음) | 맵을 오갈수록 누적 |
