## 1. 규칙

### 공통

| 항목 | 값 |
|---|---|
| 체력 | **1** — 1 이상 맞으면 죽는다 (누에고치와 같은 판정) |
| 막음 | **있음** (`is_block`) → 움직이는 벽이자 격노의 브레이크 |
| 행동 | 플레이어가 한 번 행동한 뒤 **한 칸** |
| 플레이어 피해 | 가려는 칸에 플레이어가 있으면 **때리고 제자리에 선다** (기본 1) |
| 낙하 | 구멍 위에 멈추면 떨어져 죽는다 (상자·플레이어와 같은 규칙) |
| 처치 수단 | 플레이어 공격 / **상자에 치임** / **고추를 밟음** / 구멍 |
| 포탈 | **잠그지 않는다.** 목표가 아니라 장애물이자 도구다 |

### 두 종류

| | 순찰형 `patrol` | 추적형 `chase` |
|---|---|---|
| 행동 | 바라보는 방향으로 1칸. 막히면 **방향만 뒤집고 그 턴은 쉰다** | 플레이어 쪽으로 1칸. **먼 축 우선, 동률이면 가로** |
| JSON | `{"obj_type":"goblin","dir":"L"}` | `{"obj_type":"goblin","move":"chase"}` |
| 성격 | 예측 가능한 시계 → 타이밍·패리티 퍼즐 | 내 위치의 거울 → 유도 퍼즐 |

막혔을 때 **"뒤집고 쉰다"**로 정한 이유: 뒤집고 바로 움직이면 한 턴에 두 칸처럼 보여서
플레이어가 왕복 주기를 셀 수 없다. 추적형의 축 우선순위도 **고정**이다 —
난수가 섞이면 퍼즐이 아니라 운이 된다.

### 왜 이게 재미있는가 — 감정 시스템과 곱해진다

`공격력 = 원래 공격력 − 이동한 칸수`가 처음으로 **생사를 가른다.**

| 감정 | 이동 | 공격 | 고블린을 죽이려면 |
|---|---|---|---|
| 평온 (hp 4~6) | 1 | 1 | **제자리에서만** (1칸 걸으면 공격력 0) |
| 화남 (hp 2~3) | 1 | 2 | 걸어가면서 때릴 수 있다 |
| 격노 (hp 1) | 2 | 2 | **부딪힌 것만** (2칸 가면 공격력 0) |

그리고 반대 방향으로도 — 고블린은 **걸어다니는 고추**다.
1월드의 고추가 "내가 밟기로 선택하는" 자원이었다면, 고블린은 **나를 찾아오는** 자원이다.
벽(ma=2)을 부수려면 공격력 2가 필요한데 지금 평온이라면, **일부러 맞으면 된다.**

## 2. 커리큘럼

2월드의 교훈을 반영했다. 2월드는 평온 구간에 **5스테이지**를 썼고(1월드는 2개) 그래서
"플레이어에게 전부 가르쳐 주는" 느낌이 됐다. 3월드는 **가르치는 구간을 2스테이지로 끊고,
3-3부터는 반드시 기존 요소와 조합**한다.

| 스테이지 | 가르치는 것 | 조합 |
|---|---|---|
| **3-1** | 고블린은 막는다. 평온은 **제자리에서만** 죽일 수 있다 | — |
| **3-2** | 순찰은 주기가 있다. **기다리는 수**도 수다 | 벽 |
| **3-3** | **일부러 맞아 화남이 되어야** ma=2 벽을 부순다 | 추적형 + 파괴 가능 벽 |
| **3-4** | 추적형은 **나를 따라오다 구멍에 빠진다** | 추적형 + 구멍 |
| **3-5** | 고블린 몸은 **격노의 브레이크**다 (패리티 전환) | 격노 + 구멍 |
| **3-6** | 움직이는 방해물이 있는 **순회** 퍼즐 | 누에고치 ×2 + 순찰형 |
| **3-7** | **상자로** 멀리서 처치한다 | 격노 + 상자 + 누에고치 |
| **3-8** | 양쪽에서 조여온다. 출구가 ma=2 벽으로 봉인돼 있다 | 순찰 + 추적 + 누에고치 ×2 + 벽 |
| **3-9** | 격노로 시작한다 — **어떤 접촉도 즉사** | 격노 + 상자 + 누에고치 ×2 + 고블린 ×2 |
| **3-10** | 전부 | 누에고치 ×3 + 상자 + 고블린 ×2 + 봉인된 출구 |

### 3-5를 4수로 둔 이유

짧다. 그런데 **소프트락이 44%**다. 고블린을 잘못 쓰면 되돌리기 없이는 끝이다.
작가님의 1월드 난이도 곡선은 `7, 5, 13, 16, 8, 28, 7, 20, 23`로 **톱니**다 —
길게 응용한 뒤 짧고 날카롭게 끊는 패턴. 3-5와 3-7이 그 역할이다.

## 3. 검증 결과

`tools/level_sim`의 4종으로 전부 검증했다. 엔진 없이 확인 가능한 범위다.

| 스테이지 | 최단수 | 생존상태 | 소프트락 | 필수 감정 | 최단 해답 |
|---|---|---|---|---|---|
| 3-01 | 6 | 44 | 0 (0%) | 평온 | `RRRRRR` |
| 3-02 | 9 | 617 | 22 (4%) | 평온 | `RRRDDRRRU` |
| 3-03 | 8 | 285 | 27 (9%) | **화남** | `RRUUURRR` |
| 3-04 | 11 | 112 | 0 (0%) | 평온 | `UDDDRRRUURU` |
| 3-05 | 4 | 9 | 4 (**44%**) | **격노** | `UURR` |
| 3-06 | 13 | 4630 | 0 (0%) | 평온 | `DDDDUUURRRRRR` |
| 3-07 | 8 | 142 | 0 (0%) | **격노** | `RRRRDLLL` |
| 3-08 | 20 | 18229 | 417 (2%) | **화남** | `ULDDLUULUULDDLRRDLLD` |
| 3-09 | 10 | 40372 | 0 (0%) | **격노** | `DDDURRUURD` |
| 3-10 | 22 | **230735** | 1949 (1%) | **화남** | `UUDDDUDDRRRRDDRUUDRRUU` |

- **33개 맵 전부 클리어 가능** (1·2·3월드 + 허브 4개)
- **허브 4개 전부 순회 가능** (00_00 / 01_00 / 02_00 / 03_00)
- **카메라 잘리는 맵 0개** (전 맵이 1080×1920 안, 최대 사용률 96%)

### 2월드와 비교

| | 2월드 | 3월드 |
|---|---|---|
| 최단수 | 5,7,5,8,10,8,7,15,6,19 | 6,9,8,11,4,13,8,20,10,22 |
| 최단수 합계 | 90 | **111** |
| 생존상태 최대 | 851 | **230,735** (271배) |
| 소프트락 범위 | **47~81%** | **0~44%** |
| 화남 도달 | 2-6 | **3-3** |
| 격노 도달 | 2-9 | **3-5** |
| 감정 분포 | 평온5 / 화남3 / 격노2 | 평온4 / 화남3 / 격노3 |

**읽어야 할 핵심: 3월드는 더 어렵지만 더 공정하다.**
상태공간은 271배가 됐는데 소프트락 비율은 오히려 **크게 내려갔다.**
고블린은 플레이어를 **죽이기** 때문이다 — 죽음은 되돌리기 안내가 뜨고 한 수로 복구되는
명확한 실패지만, 2월드의 소프트락은 "살아 있는데 이미 클리어 불가"라는
**플레이어가 알 수 없는** 실패였다. 움직이는 적을 넣으면서 실패의 성질이 바뀌었다.

## 4. 구현

### 시뮬레이터
- `sim.py` — 고블린 상태(위치 + **방향**)를 상태 튜플에 추가.
  순찰 반전 / 추적 축 우선순위 / 낙하 / 함정 사망 / 상자 처치 전부 이식
- `build.py` — `^ v < >` 순찰(글자가 바라보는 방향), `X` 추적
- `render.py` — 👺 순찰(화살표로 방향), 😈 추적

검증한 상호작용 6종 (전부 통과):
순찰 반전 / 피격→감정 변화 / 추적 낙하 / 격노 공격불가 / 상자로 처치 / 고추로 처치

### Godot
| 파일 | 내용 |
|---|---|
| `01_Scripts/Entities/Element/Goblin/Goblin.gd` | 신규. `Unit` 상속 |
| `04_Scenes/Entities/goblin.tscn` | 신규. **스프라이트는 누에고치 텍스처 + 색 틴트 플레이스홀더** |
| `ActionManager._run_goblin_turn()` | 플레이어 행동 뒤 고블린 1행동. tick을 이어 붙여 연출 순서 유지 |
| `EntitySpawner.RANK` | `goblin: 50` (상자 뒤, 플레이어 앞) |
| `exported_resources.tres` | `"goblin"` 등록 |

**되돌리기**: 방향(`face`)도 상태이므로 `save_undo_state` / `apply_undo`에 넣었다.
위치는 `Unit`이 이미 처리한다. `UndoManager.pre_action()`이 턴 시작에 전체를
스냅샷하므로 고블린 턴의 결과도 함께 되돌아간다.

### 곁가지로 고친 것 — I-8 (상자/고블린이 목표 포탈을 밟아 클리어)

`Portal._check_pos`가 엘리먼트 종류를 가리지 않아서 **상자가 목표 포탈에 멈추면
클리어**됐다. 지금까지는 배치로 피해 왔지만, **고블린은 매 턴 저절로 움직이므로
피할 수 없다.** 설계 중 실제로 터졌다(테스트 맵이 2수로 클리어됐다).
`if not (elm is Player): return`을 넣어 고쳤다. 기존 22개 맵의 최단 해답은 변화 없다.
