## 1. 엔딩 연출

`01_Scripts/UI/EndingDirector.gd` + `04_Scenes/ending.tscn` (main.tscn에 인스턴스)

### 흐름

| 단계 | 내용 |
|---|---|
| 트리거 | 2-10 클리어 → `StageContext.stage_completed(2, 10)` |
| ① | 입력 차단(`InputManager.can_interact = false`) 후 **허브 로드가 끝날 때까지 대기** |
| ② | `SceneTransition.fade_out()` — 검은 화면으로 |
| ③ | HUD 숨김 + 엔딩 레이어 표시 → `fade_in()` → **클리어 화면** |
| ④ | 크레딧이 위로 흐른다. **누르고 있으면 2배 속도** |
| ⑤ | `comming soon...`이 **화면 정중앙**에 오면 멈춘다 |
| ⑥ | 손을 떼고 다시 누르면 `fade_out` → **처음 게임 시작 화면** → `fade_in` |

### 왜 허브 로드를 기다리는가

`complete_stage()`는 **턴 도중**(`ClearPortal.move_map`) 불린다. 거기서 바로 디졸브를
시작하면 클리어 연출과 페이드가 겹치고, 허브 로드가 페이드 중간에 터져 나온다.
그래서 `_pending` 플래그만 세우고 **`StageDirector.stage_loaded`를 기다린다.**
턴 파이프라인에는 손대지 않았다 — 허브는 평소대로 로드되고 엔딩 레이어가 그 위를 덮는다.

### 크레딧 멈춤 지점 계산

```gdscript
screen_center = credits_root.size.y * 0.5
line_center   = coming_soon.position.y + coming_soon.size.y * 0.5
limit         = screen_center - line_center
```

`ComingSoon`은 `Scroller`(VBoxContainer)의 자식이라 위치가 컨테이너 기준이다.
레이아웃이 끝난 뒤의 **실측값을 매 프레임 다시 읽는다** — 글자량을 바꿔도 멈춤 지점이 자동으로 맞는다.

### "아래로 내려가고"의 해석

요청은 "크레딧이 아래로 내려가고, 가장 밑에 글씨가 화면 정중앙에 갈 때까지"였다.
**가장 밑 줄이 정중앙에 오려면 텍스트는 위로 움직여야** 한다(= 읽는 위치가 아래로 내려간다).
일반적인 크레딧 롤과 같은 방향으로 구현했다. 반대였다면 알려줄 것.

### 에디터에서 조절 가능

`clear_movie_dur`(3초) / `scroll_speed`(110 px/s) / `fast_multiplier`(2배) /
`final_world`(2) / `final_stage`(10) 전부 `@export`다.

현재 글자량에서 전체 스크롤은 **약 30초**(누르면 15초)다. 길면 `scroll_speed`를 올린다.

### 남은 자산

- [ ] **클리어 영상** — 지금은 `CLEAR` 글자 플레이스홀더를 3초 보여준다.
      `ClearMovie` 아래에 `VideoStreamPlayer`를 넣고 `_play_clear_movie()`만 바꾸면 된다
- [ ] **크레딧 이름** — 역할만 올라가고 이름이 없다.
      `EndingDirector.CREDITS_TEXT` 상수에 바로 써넣으면 된다
- 효과음은 **쓰이지 않던 `clear_world.wav`**를 엔딩 시작음으로 붙였다

### 확인 필요

- `comming soon...`은 **요청한 철자 그대로** 썼다. `coming`이 맞는 철자이니 의도인지 확인
- PC 테스트를 위해 **마우스 클릭과 키 입력도** 누름으로 인식하게 해뒀다

## 2. 감정 화면 틴트

`01_Scripts/UI/EmotionTint.gd` (main.tscn의 `EmotionTint` 노드)

### 방식

`RenderingServer.set_default_clear_color()`로 **화면 배경색 자체**를 바꾼다.
맵을 볼 때 항상 시야에 들어오는 면이라 아주 옅게 깔아도 상태가 계속 느껴진다.

| 감정 | 색 | 비고 |
|---|---|---|
| 평온 (hp 4~6) | `0.91, 0.91, 0.91` | `project.godot`의 원래 배경색과 동일 |
| 화남 (hp 2~3) | `0.93, 0.85, 0.83` | 아주 옅게 |
| 격노 (hp 1) | `0.95, 0.76, 0.72` | "살짝"의 범위를 넘지 않게 |
| 사망·낙하 | 평온색 | 감정이랄 게 없으므로 원래 색으로 |

### 틱 없이 변하게 하는 부분

```gdscript
_current = _current.lerp(target, 1.0 - exp(-LERP_SPEED * delta))
```

`1 - exp(-k·dt)` 지수 보간이라 **프레임 간격이 흔들려도 수렴 속도가 같다.**
`LERP_SPEED = 4.0`이면 체감상 0.3~0.5초에 걸쳐 슥 바뀐다. 더 느리게/빠르게는 이 값만 조절.

### 왜 시그널이 아니라 폴링인가

`player_emotion_changed`를 구독하면 **스테이지마다 새 플레이어에 다시 연결**해야 하고,
리셋·되돌리기로 감정이 되돌아갈 때의 초기 동기화도 따로 챙겨야 한다.
어차피 매 프레임 보간하는 연출이므로 매 프레임 목표색을 다시 계산하는 쪽이
연결 수명 관리가 없어 더 안전하다.

- 색이 **너무 약하거나 너무 센지**. 상수 3개만 바꾸면 된다
- 허브(월드맵)에서는 체력 6이라 자동으로 평온색이다. 의도대로인지
